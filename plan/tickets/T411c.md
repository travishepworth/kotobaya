## Do
- `MediaPublishRunner(db, opApply, objectStore)` with `start(scope)` (W-5 calls it): claims only the C-11 internal kind, verifies parent not cancelled, fetches + verifies the snapshot blobs, and in ONE transaction: `media.created` + `deck.created` on first publish, replace the media's segments/sentences/occurrences (and detected spans) and the media deck's `deck_item` rows from the snapshots, `media.content_published` (next version, `parsed`) and `deck.content_published`; writes `JobResultMedia` to the parent. Also the `failed`/`parsing` transitions C-11 assigns to the server.
- Snapshot reader per SNAPSHOT.md (Kotlin, shared later by devices if wanted — keep it free of server-only types in its own file).
- Idempotent: a re-claimed or retried child whose version is already published changes nothing and reports the existing result.

## Acceptance (each bullet → at least one named test)
- [ ] **Op apply idempotency (mandatory, CLAUDE.md):** running the same child twice yields one set of ops and identical rows; a crash (exception) mid-transaction leaves no rows and no ops; parent cancelled → nothing applied.
- [ ] Order: `media.created` then `deck.created` (with `caused_by_op_id`) then content ops; first vs second publish (only content ops on the second; version n+1); `parse_status` transitions match C-11.
- [ ] Sentence ids from the snapshot are kept across re-publish; occurrences/segments of the old version are gone; manual grammar spans untouched.
- [ ] Mapping queue rows populated from `unmapped` per C-11.
- [ ] `make check MODULE=server` green.
