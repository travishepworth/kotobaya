## Do
Kotlin interfaces + data classes (no implementations) in `core/src/commonMain/kotlin/kotobaya/contracts/`, with KDoc stating exact semantics, edge cases and invariants:
- `Scheduler` (FSRS-6; inputs/outputs matching the DB FSRS columns and the fixtures/fsrs vector format; preview of the 4 ratings' intervals).
- `ReplayEngine` (pure function of the replay set ordered by (reviewed_at, hlc, id), effective preset, core version; incremental fold only when weights_version matches and the new review sorts after the last folded one; otherwise full replay; earliest-undo-wins; merged replay sets via merged_into_id).
- `QueueBuilder`, `CardGenerator`, `HotScorer`.
- `SearchQueryParser` with the AST and `complete(prefix)` for autocomplete; the search language grammar in EBNF at `contracts/core/search.ebnf`.
- `CardRenderer` (note + card kind + options such as furigana on/off and pitch on/off → sanitised HTML fragment using only classes from `assets/card/`).
- `Hlc` (format, compare, mint/observe, `mint_at` per SYNC §3.2) and `OpCodec` (encode/decode ops per contracts/sync schemas, including the lenient unknown-op path and max_op_bytes measured on raw UTF-8 compact JSON).
- `CoreJs` facade: exactly what is `@JsExport`ed to the web (search parse/complete, card render, FSRS interval preview), with JS-friendly types (no Long or collections in signatures).
- `contracts/core/README.md` mapping each interface to the spec/SYNC sections and listing the tests implementers must write (FSRS golden vectors; SYNC worked examples incl. `clock-behind-remint`, `ahead_story`, `merge-two-level-cards`; device-side append-only for review_log/change and earliest-undo-wins, which have no SQLite trigger). `contracts/core/SUMMARY.md` for the human (decisions, rejected alternatives, 3 choices worth a second look).
