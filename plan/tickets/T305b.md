## Read
- Spec: Dictionary and search (JMdict matching); Notes and cards (card kinds, `add_kanji`); Sync and offline (offline adds, same word on two devices); Clients › Takoboto integration ('matched to a JMdict entry locally, saved offline, and synced later')
- Contracts: contracts/sync/SYNC.md §4 (creating notes/cards offline, 'no knowing duplicates'), §8 (duplicate merge, esp. 8.1 trigger and 8.6 'on the device that created the duplicate'), §12.3; contracts/sync/ops note.created, card.created, deck.item_put, word.status_set; contracts/core/ `CardGenerator`, `CardRenderer` (front-empty check); contracts/db/SCHEMA.md `note`, `card`, `deck`, `entry_seq`; T302 `DictionaryProvider`; T303a `OpMinter`
- Follow-ups folded in: "T201a -> T213a/T201b: CardGenerator (contract signature has no note fields) doesn't skip a card kind whose front template renders empty; the caller (T201b note create, using T213a rendering) must apply the 'skip empty front' rule" (apply it here, same as the server's note create); "Freeze A: jpdb-import kanji dedupe vs a concurrent offline phone add goes through SYNC 8 merge"

## Do
- `NoteCreator.create(request)` where `request` = (word and/or reading, optional sentence, source/app, optional deck, tags, raw fields): matches a JMdict entry locally (exact kanji+reading, then reading, with a stable tie-break and a 'no match' result that still creates a deckless note flagged for later matching), detects a **local** duplicate (same entry/word already live: returns `Duplicate(existing)` and creates nothing unless forced), generates cards via core `CardGenerator` + the front-empty rule, and mints `note.created`, `card.created`, optional `deck.item_put` in ONE transaction through `OpMinter`.
- Deterministic ids: note/card ids UUIDv7 from the minter; never reuse ids across retries (a retried request with the same request id returns the same note).
- Expose `DuplicateCheck.find(...)` (used by T305c for AnkiDroid's duplicate query and by T311 for `canAddNotes`).
- Koin module + registration line in `di/FeatureModules.kt` (flag in HANDOFF).

## Acceptance
- [ ] Matching tests on a fixture dictionary: kanji+reading hit, reading-only ambiguous (tie-break stable), no match.
- [ ] Create produces exactly the expected ops (types, order, payloads validate against the op schemas) and local rows; killing before commit leaves nothing; a retried request id is idempotent.
- [ ] Duplicate detection: second add of the same word is reported; `force` creates a knowing duplicate per SYNC §4 rules.
- [ ] Two simulated devices add the same word offline; after sync both converge on one survivor via §8 (uses T303b/T303c fixtures).
- [ ] Empty-front kinds are skipped.
- [ ] `make check MODULE=android` green.
