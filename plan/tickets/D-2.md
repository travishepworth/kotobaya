# D-2 — Stop leaking anonymous Docker volumes from tests/tools

- Phase: P5 (infra) · Model: sonnet · Risk: low
- Deps: none
- Branch: t/D-2-volume-leak
- Owned paths (only edit these): test-infrastructure only — Testcontainers setup/helpers in
  `server/src/test/`, `acceptance/`, `worker/tests/conftest.py` (and similar fixtures),
  `testcontainers.properties` files in the repo, Gradle test config (`*/build.gradle.kts` test
  blocks only), `Makefile`, dev compose files under `deploy/`. List every path touched in HANDOFF.
- Module(s) for CI: server (plus any other module you touch)

## Context
195 local Docker volumes (~21 GB reclaimable) have leaked again, despite an earlier fix for the
Postgres Testcontainers image. Suspects: other Testcontainers images (SeaweedFS/MinIO, etc.), the
compose dev stack (`make dev-up/dev-down` without `-v`?), Gradle test JVMs killed before Ryuk
cleanup, worker pytest containers, images that declare `VOLUME` (each run creates an anonymous
volume unless removed with the container's volumes).

## Do
1. Diagnose from evidence: `docker volume ls`, `docker volume inspect` (labels such as
   `org.testcontainers*`, `com.docker.compose.*`, CreatedAt), `docker ps -a` for stopped containers
   holding volumes, and `docker image inspect` for images with `VOLUME` declarations. Group the 195
   volumes by origin (counts per origin) and map each origin to the test/tool that creates it.
2. Fix each origin at the source: e.g. remove containers with their volumes, tmpfs mounts instead of
   anonymous volumes for test DBs/object stores, `down -v` for the dev stack's throwaway volumes
   (keep named persistent volumes the dev stack needs), Ryuk enabled / reuse settings, shutdown hooks.
3. Verify with ONE small targeted test run (one test class, not a whole module suite): count volumes
   before and after; the count must not grow.

## Hard limits
- **Never** run `docker volume prune`, `docker volume rm`, `docker system prune`, or delete any
  existing volume/container you did not create in your own verification run. Report counts only.
- Machine is resource-constrained: no full-module Gradle test suites beyond the final
  `make check MODULE=server`; check `df -h /` first and stop (BLOCKED) if under 10 GB free.

## Acceptance
- [ ] HANDOFF lists volume origins with counts and the fix for each (or why it is left).
- [ ] A targeted test run leaves the volume count unchanged.
- [ ] `make check` green for each touched module.

## Out of scope
Pruning existing volumes (the human does that; put the exact command in HANDOFF under Notes).
