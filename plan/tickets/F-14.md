# F-14 — Blob PUT fails against SeaweedFS (Content-MD5 mismatch)
- Phase: P4 (hotfix, human-reported from live 0.1.1) · Model: sonnet · Risk: med (blob uploads lost) · Deps: none
- Owned paths (only edit these): `server/src/main/kotlin/kotobaya/blobs/`, `server/src/test/kotlin/kotobaya/blobs/`, `server/src/main/kotlin/kotobaya/server/ObjectStore.kt`, `server/build.gradle.kts` (test deps only), `gradle/libs.versions.toml` if present (lockfiles), `docs/DECISIONS.md` (append ADR only if changing minio/SeaweedFS version)
- Spec: docs/SPEC.md media/blob storage; ADR-003 (SeaweedFS replaces MinIO). Contracts: contracts/api blobs endpoints (read only).

## Problem
Live deployment: blob PUT fails against bundled SeaweedFS `chrislusf/seaweedfs:3.80` (pinned in docker-compose.yml and deploy/helm/kotobaya/values.yaml).
SeaweedFS log: "The Content-Md5 you specified did not match what we received" (s3api_object_handlers_put.go:161).
Code: `S3BlobStore.put` → `PutObjectArgs.stream(input, -1, PART_SIZE)` — unknown length, 16 MiB parts, plain http://kotobaya-objectstore:8333, minio-java 8.5.14. The worker's Python client uploads to the same bucket fine. The in-memory store used in tests hid this.

## Fix
Make uploads work against SeaweedFS 3.80. Options: pass a known length (stream already length-known from Content-Length, or spool to a temp file / buffer bounded by the blob size cap), a different upload path, or a minio/SeaweedFS version change via ADR. Prefer the smallest reversible fix; keep SHA-256 verification semantics unchanged; temp files must be cleaned up on every path.

## Acceptance
- Testcontainers test against `chrislusf/seaweedfs:3.80` (same image as compose/helm): PUT small blob, PUT blob > 16 MiB (multipart), GET round-trips byte-identical; hash mismatch still rejected.
- `make check MODULE=server` green.
