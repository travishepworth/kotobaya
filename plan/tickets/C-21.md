## Problem (live 0.1.9)
JLPT list decks show 0 words: there is no JLPT vocabulary source anywhere (only ref.kanji.jlpt and grammar_point.jlpt), and no worker handles `deck-build`. freq_list/entry_freq are empty too (live config has no `freq_lists`).

## Do
Define, additively, where JLPT vocabulary-list membership lives and how it is loaded, so that (a) the server can count list items for `/deck-lists`, and (b) the worker `deck-build` job can build a JLPT or frequency list deck's deck-items archive (SNAPSHOT.md) for the existing media-publish path.
- Prefer reusing existing tables if they fit (e.g. a JLPT level as a "list" in freq_list/entry_freq, or a new `ref.vocab_list_item(list_key, entry_id, rank)`); pick the smallest clean option and record it as a provisional ADR in docs/DECISIONS.md.
- Choose the data source and record its licence in the ADR: a JLPT vocabulary list with a redistributable licence (e.g. Jonathan Waller's tanos.co.uk lists, CC BY; or a derived repo that keeps CC BY attribution). Say how entries are matched to dict_entry (kanji form + reading → entry id) and that unmatched rows are counted and reported, never silently dropped.
- Specify the `deck-build` job semantics if anything is missing: input, which list (JLPT level vs frequency band), item order, result counts (JobResultDeckBuild), behaviour when the source is empty (fail, not publish an empty deck).
- Migration file if schema changes (next V number); regenerate clients; `make check MODULE=contracts` green.
- Leave a short implementation note in HANDOFF for the follow-on ticket JLPT-1 (worker loader + deck-build handler + server DeckLists counts).
