## Do
- Single-user password with argon2id (parameters documented; use a library already on the classpath or justify one new dependency in HANDOFF). Define the first-run password setup path (env/secret or CLI subcommand; document it).
- Optional TOTP (RFC 6238).
- `POST /auth/login` issues an `api_token` of kind `session` with all five scopes and cookie `kotobaya_session` (`HttpOnly; Secure; SameSite=Strict; Path=/api`). `/auth/logout` revokes it; `/auth/session` reports it. The Authorization header wins over the cookie when both are present.
- Brute-force rate limit on login (per remote address and global) returning the documented problem type; in-memory.
- Fill T104's `Authenticator` hook with a token validator that T105b reuses: hash lookup; revoked/expired/device-revoked checks; cache of at most 5 s that is invalidated on revoke so revocation is visible at once.
- Request logs carry `token.id` and `token.name`. This is the audit trail; openapi §2 says there is no audit table in v1, which supersedes the backlog line "structured audit log lines plus `change.token_id` (openapi §2: no audit table in v1)".

## Acceptance (named tests)

- [ ] Logout and revocation take effect on the very next request (no cache lag).
- [ ] Cookie attributes asserted; token strings match the format; only the hash is stored.
