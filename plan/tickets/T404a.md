## Do
- `snapshot.py`: writers (and readers, for tests) for both C-11 archive formats from typed records (`SegmentRec`, `SentenceRec`, `OccurrenceRec`, `DeckItemRec`); deterministic bytes for identical input (stable ordering) so a retry produces the same hash.
- `ids.py`: `assign_ids(media_id, existing, new_segments)`: reuse segment ids by ordinal and sentence ids by `(segment ordinal, sentence ordinal, text)`; mint UUIDv7 otherwise. `existing` read from `app.media_segment`/`app.sentence` by a small repo (read-only).
- `blobs.py`: upload bytes to S3 under their SHA-256 and insert the `app.blob` row after the object is durable (idempotent; existing hash = no-op).
- `handoff.py`: `publish(ctx, PublishRequest) -> JobResultMedia`: build + upload snapshots, enqueue the `media-publish` child per C-11 (adopt an existing one on retry), wait for it honouring cancellation, return the server's result.
- Everything injectable (S3, DB, clock) with in-memory fakes for unit tests.

## Acceptance (each bullet → at least one named test)
- [ ] Snapshot round-trip: write → read gives the same records; output validates against C-11's schemas/check tool; identical input → identical hash.
- [ ] **Id stability (data-integrity test):** re-publishing a media with one sentence edited keeps every other sentence id and all segment ids; an inserted sentence shifts ordinals → those sentences get new ids, unchanged ones keep theirs (rule exactly as in the contract).
- [ ] Retry: a second `publish` for the same parent adopts the existing child; no second upload row; blob upload idempotent.
- [ ] `make check MODULE=worker` green (Postgres-backed tests as in `test_jpdb_apply_pg.py`).
