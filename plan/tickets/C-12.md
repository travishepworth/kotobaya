## Do
1. **Freeze the token element** stored in `sentence.tokens`, carried in snapshots and returned by `/parse`: fields, types, which are optional; offsets are UTF-16 code units into the ORIGINAL (not normalised) text, half-open, ascending, non-overlapping; `seq` null = unmapped; `override` flag; `class` values = `occurrence.pos_class`. Align openapi's token schema if it differs (additive).
2. **`class` derivation**: a deterministic table from Sudachi POS (and JMdict name/particle tags) to `content|particle|auxiliary|name|other`, plus the tie-break for `occurrence.pos_class` ("most frequent use in this segment"; equal counts -> fixed order). Coverage filters and the i+1 definition depend on it.
3. **Override application**: matching on original vs normalised text, overlapping overrides (scope sentence > media > global, then longest `match_text`, then highest hlc; leftmost-first scan), how replacement tokens get `reading`/`pos`/`class` when the override omits them, `seq: null` = forced "no entry", and that `/parse` applies global overrides only.
4. **Worker parse service** used by the server for `POST /parse` (synchronous): transport (recommended: small internal HTTP endpoint on the worker, cluster-internal only, e.g. `POST /internal/parse` on a configured port), request/response (sentences + tokens; the server adds the `entries` summary with status/note_id), size limit (20,000 chars, same as the API), timeout and the server's `503 unavailable` mapping, health, and the env var names (`PARSER_URL` on the API, port on the worker) so W-5 can wire Helm/compose. No auth beyond network policy is acceptable if stated; otherwise define a shared-secret header.
5. Note in SUMMARY which parts are versioned (a `parser_version` string in `JobResultMedia` or the snapshot header, so re-parse decisions can be made later) — additive and optional.
