## Do
- JVM simulation, no devices: two (and some runs three) simulated devices, each = real T303 client stack (`OpMinter`, `SyncEngine`, `DeviceOpApplier`, in-memory `DeviceStore`) with its own clock; server = the real server sync/apply code (`:server` OpApply + Postgres via Testcontainers, reusing one container with truncation between runs) if available in the test environment, with the in-memory reference replica as the oracle; if Docker is unavailable, run against the in-memory reference server and say so in the report.
- Simulated offline week: days of reviews (all buttons, undo), note adds (incl. the same word on both devices, via Takoboto-style `NoteCreator` requests), edits (note fields, preset update/publish, `card.preset_set`), deletes, suspends/buries, word statuses, deck items (`e:` and `n:` keys), a server-originated import-like add, clock skew +-10 minutes per device with drift, occasional large clock jumps (ahead and behind) followed by Re-mint/Discard/Retry choices, a server restore from backup mid-week, devices killed mid-push, lost responses; then final syncs in random orders and interleavings.
- Oracle per SYNC §11: all replicas and the server agree on every table projection and card cache; **zero lost reviews**: every `review.logged` created on any device and not explicitly undone or user-discarded (tracked in the sim) is present on every replica; no card cache differs from a full replay.
- Deterministic by seed; failures print the seed and a shrunk action trace; a `-Pseeds=` knob; default 100 randomised runs.
- Report (stdout/`build/reports`): per-run action counts, skew-ordering anomalies seen, Re-mint outcomes.
