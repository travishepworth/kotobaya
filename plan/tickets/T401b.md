## Do
- `make_jpdb_deck_import(...) -> Handler` for job kind `jpdb-deck-import` (registration is W-5): read payload (`jpdb_id`, `media_id`, title/kind/deck), fetch via T401a (cache), map each row with `map_vocab` after applying stored mapping corrections (C-11) first, merge rows mapping to the same seq (sum counts, keep best rank), compute deck positions by in-deck frequency (1 = most frequent; tie by seq), build one `whole` segment with `token_count = sum(counts)` and `unmapped_token_count` = counts of unmapped/ignored rows, occurrences (`pos_class` per the C-12 table applied to the dictionary entry POS; `content` if undeterminable), and the deck-item snapshot.
- Hand off through the T404a kit (content + deck snapshots, `media-publish` child per C-11) and return `JobResultMedia` with `unmapped` listing every unmapped row (`jpdb_vid`, spelling, reading, occurrence_count); populate the unmapped queue as C-11 specifies.
- `remap_only`/re-import from cache per C-11: no network calls when the cache holds the deck.
- Progress via `ctx.progress`; cancellation honoured between pages.

## Acceptance (each bullet → at least one named test)

- [ ] Snapshot produced by the handler validates against C-11's record schemas; `token_count = sum(occurrence.count) + unmapped_token_count`.
- [ ] Re-running the same job (retry) produces an identical snapshot and adopts the existing child (no second publish).
- [ ] `make check MODULE=worker` green (Postgres-backed tests follow the existing `test_jpdb_apply_pg.py` pattern).
