## Read
- Spec: Clients › Android app › Other ways in (on-device AnkiConnect-compatible server on localhost, for Yomitan in mobile browsers); Public API (any AnkiConnect notes)
- Existing: T305b `NoteCreator`/`DuplicateCheck`; T305c deck and note-type listing (`AnkiStore` semantics) if merged; web or server AnkiConnect layer if one exists (`server/` grep `ankiconnect`, parity only, read-only)
- Decisions: Security: localhost only

## Do
- Foreground-service-free, user-toggled local HTTP server (embedded engine already in the project's dependency set if possible, otherwise record the new dependency in HANDOFF) bound to `127.0.0.1` ONLY on a configurable port (default 8765), CORS as AnkiConnect (`Access-Control-Allow-Origin` per setting with Yomitan origins), AnkiConnect protocol v6 envelope `{action, version, params}` -> `{result, error}`; optional `apiKey`.
- Actions Yomitan needs: `version`, `deckNames`, `deckNamesAndIds`, `modelNames`, `modelNamesAndIds`, `modelFieldNames`, `canAddNotes`, `canAddNotesWithErrorDetail`, `addNote`, `storeMediaFile` (store to blob cache, attach on note), `findNotes` (basic), `notesInfo` (basic), `requestPermission`, `multi`; unknown actions return the AnkiConnect error shape. Reuse `NoteCreator` so every note becomes ops.
- Settings screen: toggle, port, API key, status.

## Acceptance
- [ ] Yomitan-compatible request fixtures (`android/src/test/resources/ankiconnect/*.json`: request and expected response for each action above, taken from AnkiConnect's documented examples) all pass against the handler.
- [ ] Binding test: the server socket is bound to loopback only (assert the bound address; a connection attempt via a non-loopback interface address fails where the test environment has one).
- [ ] Origin/API-key tests; `addNote` duplicate returns the AnkiConnect duplicate error; `multi` batches.
- [ ] `make check MODULE=android` green.
