## Do (each is a wording, comment or additive change; no column or op removed or renamed)
1. SCHEMA.md §4.2: replay order is `(reviewed_at, hlc, id)`, matching SYNC.md §9.1. SYNC wins; fix every place in SCHEMA.md/V1 comments that still says `(hlc, id)`.
2. `card.last_review_at` semantics (V1__init.sql comment + SCHEMA.md + matching .sq comment + SYNC §9 where it defines the cache): `last_review_at` = `reviewed_at` of the last **rated** (non-manual) replay row. Manual rows (set_due / reschedule / reset) leave it unchanged; `last_review_id` may still name the manual row. Reset clears it to NULL (the card is new again). State that fold still equals replay under this rule. Why: otherwise a review right after a reschedule uses FSRS's same-day formula (S≈26 d instead of ≈3.5 d after a lapse).
3. sync_state key `core_scheduler_version`: add to SYNC.md §10.5 and to the device Local.sq documentation/seed (whatever the other sync_state keys use). Semantics: when the app's core scheduler version differs from the stored one, the device does a full replay of every card's cache before folding anything, then stores the new version; the rebuild keeps this key. Say where the server stores its equivalent (a `meta`/settings row or an existing table — pick the existing mechanism; additive only).
4. SYNC.md §6.1: a pulled op that fails its own schema is treated like an unknown op: the device stops pulling at it, never skips it, and surfaces "update required / server sent invalid op". (Extends "devices never validate pulled ops".)
5. SYNC.md §5.3: the server measures `op_too_large` as `utf8Size(canonical compact JSON of the op tree)` **before** decoding/validating, for every op including unsupported or invalid ones. Canonical form = raw UTF-8, no escaping beyond what JSON requires, members in canonical order (T006's CanonicalJson defines the exact form; reference it by name).
6. `fsrs_params.published` schema (contracts/sync/ops): bound each weight to the py-fsrs 6.3.2 parameter bounds (lower/upper per index), so out-of-range weights are rejected at push (`schema_invalid`) instead of producing stability ≤ 0 or NaN at apply. If per-index bounds are awkward in JSON Schema, use `prefixItems` with min/max per index.
