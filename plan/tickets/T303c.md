## Do
- `SqlDelightDeviceStore`: implements `DeviceStore` over the generated queries; one SQLDelight transaction per `transaction {}`; WAL, `synchronous=FULL` for the outbox write path so a process kill loses nothing; `MetaLimitsStore` wired into T303a's limits check.
- `SyncTransport` over T301b's HTTP client, with `Kotobaya-Seq`/epoch handling as T303a defines.
- Orchestration: `SyncCoordinator` (single-flight mutex; triggers: app open, after review session, manual 'sync now', connectivity regained, WorkManager). Startup: run `StartupReplay` before anything else.
- WorkManager: periodic (about 15 min, constraints: network connected) plus expedited one-shot after local changes; exponential backoff using T303a's pure policy; unique work names; survives reboot.
- Connectivity and server reachability: `ConnectivityManager` callback + `ServerReachability` probe so 'offline' and 'server unreachable' are distinct; sync is skipped (not failed) when offline.
- `SyncStatusRepository`: Flow of T303a `SyncStatus` for the chip (T303e): includes pending/rejected counts, last sync, 'sync stale > 2 days' boolean, diagnostics (refused-cache cards, upgrade-required info).
- `RejectedOps` store hooks the actions of T303d need (only the DB-facing methods; the logic is T303d).
- Koin module + one registration line in `di/FeatureModules.kt` (flag in HANDOFF).
