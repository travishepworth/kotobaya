## Do
- Implement `CardGenerator`: given a note (base type, fields, note type templates, enabled optional kinds) and the live cards, return the card kinds to create / which are now missing. Defaults per Scheduling: vocab meaning + reading (optional listening, production, pitch); kanji keyword (optional writing, components); phrase meaning (production, listening); grammar cloze (production, recognition, spot); sentence comprehension (listening); custom basic. Skip a kind whose template renders empty for the note (e.g. no audio). Toggling an optional kind on yields card creates for existing notes; toggling it off never deletes cards (returns nothing; suspend/delete is a user action).
- Built-in note types as Kotlin constants matching the V1 seeds exactly (ids, fields, templates); add a drift test comparing them with the seed rows parsed from `contracts/db/V1__init.sql` (read the file at test time via the jvm test source set only).
- Template field substitution helper in `kotobaya.cards` (e.g. `TemplateFields`): `{{field}}` substitution with HTML escaping, empty-section handling, `{{FrontSide}}`, per the contract's template language. T213a builds the full renderer (furigana, pitch, audio, sanitiser) on top of it; export a small public API and document it. Explicit API mode: every public member needs KDoc/visibility.
- Card ids are chosen by the caller (UUIDv7 passed in); generator is pure and deterministic.

## Acceptance (each bullet → at least one named test)
- [ ] Creating each note type (vocab, kanji, phrase, grammar, sentence, custom) yields the spec's default cards, table-driven.
- [ ] Enabling/disabling optional kinds toggles creation correctly; disabling creates nothing and never lists deletions.
- [ ] Substitution escapes HTML in field values (script/handler text stays inert) and handles missing fields and sections.
- [ ] Drift test: built-in note types equal the V1 seeds.
- [ ] `make check MODULE=core` green (jvm and js targets).
