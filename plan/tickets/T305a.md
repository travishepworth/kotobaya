## Do
- Product flavors: `ankidroid` (applicationId `com.ichi2.anki`, **the default**: `defaultConfig`/IDE default/the artifact `make apk` produces, release asset named plainly) and `own` (applicationId `kotobaya.android`). Both declare the provider authority and permission as in the spike. Document in HANDOFF that only one app per device can own them (uninstall AnkiDroid or the other flavor) and that `namespace`/package of code stays `kotobaya.android`.
- Make sure `make check MODULE=android` and `make apk` still work with flavors (a single aggregate task for tests; the default flavor for `make apk`).
- Provider layer, ported from the spike and rewritten against an `AnkiStore` interface instead of `MemoryStore`: decks, models, fields, templates, notes (`notes`, `notes_v2`), duplicate query (`mid=`, `csum in (...)`, `sfld=`), selected deck, bulkInsert, `call()`, caller-package + permission checks, field separator handling (`0x1f`), exceptions mapped as AnkiDroid does. Unknown URIs log and return empty. `AnkiStore` implementation here is an in-memory fake used by tests; the real one is T305c.
- Fixture format: `android/src/test/resources/ankiapi/*.json`, each a recorded sequence of provider calls (URI, projection, selection, args, values) and expected cursors/returns. Seed them from the spike README's URI table and AnkiDroid's `AddContentApi` call sequence (listDecks, listModels, `getFieldList`, `findDuplicateNotes`, `addNote`).
