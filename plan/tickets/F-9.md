# F-9 — Test runs must not leak Docker volumes (Testcontainers cleanup)

- Phase: P4 · Model: sonnet · Risk: low
- Deps: none
- Branch: t/F-8+F-9-build-hygiene (batched with F-8)
- Owned paths (only edit these): `server/build.gradle.kts` (test task config), `acceptance/build.gradle.kts` (test task config), `server/src/test/resources/`, `acceptance/src/test/resources/`, worker test fixtures that start containers (`worker/tests/**/conftest.py` and any shared test helper under `worker/tests/`), `Makefile` (check targets only), `HANDOFF.md`
- Module(s) for CI: server, worker (acceptance build only if touched)

## Context
Last run the host disk filled: ~178 anonymous Docker volumes (~35 GB), mostly Postgres images'
`/var/lib/postgresql/data` volumes left behind by Testcontainers runs (server/acceptance via
Testcontainers-Java, worker via testcontainers-python). Each test run leaked one or more.

## Do
1. Find why: is Ryuk disabled anywhere (`TESTCONTAINERS_RYUK_DISABLED`, `~/.testcontainers.properties`,
   build env, Makefile)? Are containers stopped without removing volumes? Are any started
   outside Testcontainers (docker run / compose) in tests?
2. Fix so every test-started container is removed **with its volumes** when the run ends, including
   on failure/interrupt where Ryuk normally covers it. Prefer: keep Ryuk enabled; for Postgres
   containers, mount the data dir as tmpfs (`/var/lib/postgresql/data`) so no anonymous volume is
   created at all (also faster). Do the equivalent in worker fixtures.
3. Do not delete or prune existing volumes/containers on the host (no `docker volume prune`, no
   `docker system prune`). Only change how tests create/clean up their own containers.

## Acceptance
- [ ] Record `docker volume ls -q | wc -l` before, run `make check MODULE=worker` and `make check MODULE=server`, record after: count unchanged (write the numbers in HANDOFF.md).
- [ ] Both checks green.

## Out of scope
Pruning existing Docker state; changing test logic.
