## Read
- Spec: Clients › Web app ("a reader with click-to-look-up and click-to-mine"; "A parse-correction tool"); Content and media import › Parsing ("fix any token in two clicks"); Architecture (real DOM text for Yomitan, ADR-002)
- Contracts: contracts/api/openapi.yaml `listMediaSentences` (segment, cursor), `Sentence` (tokens per C-12, grammar spans), `getDictEntry`, `createNote` (mining with `source_sentence`, `source_sentence_id`, `source_media_id`), `putParseOverride` / `deleteParseOverride` / `listParseOverrides`, `reparseMedia`, `parseText` (preview of a correction); C-12 token element
- Decisions: ADR-002 (card rendering from `@kotobaya/core`; the reader is app chrome, plain DOM)
- Code seams: `web/src/lib/core/` (any rendering/search logic), T405b `[id]/+layout` tab shell

## Do
- Reader: segment picker, sentences as real DOM text with tokens as spans (colour by word status; furigana from token reading toggled), timestamps/page locations shown; infinite scroll by cursor.
- Click a token → popup: dictionary entry (getDictEntry), status actions, **Mine** (createNote with the sentence and source ids; duplicate response surfaced).
- **Fix a token in ≤ 2 clicks**: from the popup, "Split here"/"Join with next"/"Change entry" opens an inline editor pre-filled with the proposed tokens; one confirm creates a `parse_override` (scope sentence by default, media/global selectable) via `putParseOverride` with a client-minted UUIDv7; banner offers "Re-parse now" (`reparseMedia`); overrides list for the media with delete.
- Strings through i18n (`lib/reader/messages.ts`).

## Acceptance (each bullet → at least one named test)
- [ ] Unit test: the override builder turns split/join/change edits into tokens whose surfaces concatenate to `match_text` (the API's 422 rule) for the fixture cases.
- [ ] Manual check documented in HANDOFF: token fix path is ≤ 2 clicks from the reader.
- [ ] `make check MODULE=web` green.
