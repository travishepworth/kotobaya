## Do
Pure library code, callable from a future job runner (T109 owns the runner; do not touch it):
- Download JMdict_e, kanjidic2 and KRADFILE (+ kradfile2 if needed for component data) with SHA-256 verification and a local cache directory (configurable, default `~/.cache/kotobaya`). The network is injected so tests never hit it. A cached file whose checksum matches is not re-downloaded.
- Parse (stream with `iterparse`; real JMdict is ~60 MB) and normalise into `ref.*` rows for one `dict_release` id. Fill `dict_entry_form.norm` exactly as SCHEMA §4.5 requires (NFKC, katakana folded to hiragana) so T106's search recipes work. `freq_rank` is left for T102.
- Loader: one transaction per release; upsert by natural key; flip `is_current`; entries missing from the new release get `retired_release_id` and lose form/gloss rows; reappearing entries reset it (SCHEMA §4.5).
- Database access via `DATABASE_URL`, which is in JDBC form (`jdbc:postgresql://host:5432/db?user=..&password=..`). The worker must accept exactly that string and convert it for its Python driver (FOLLOWUPS: env var contract). S3 settings, if touched, only via the four `S3_*` names.
- The database must be created with a UTF-8 ctype (C.UTF-8) or V1 aborts; tests that start Postgres must init it that way (FOLLOWUPS: V1 and LC_CTYPE=C).
