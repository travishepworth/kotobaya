## Request (from BUG-7 writer)
getDictEntry is one-per-seq, so the web card browser cannot label a 500-row page of referenced notes (fields `{}`, entrySeq set) without 500 requests. Rows currently show the short note id until previewed.

## Do
Add one additive, read-only operation for batch headword lookup, e.g. `GET /dictionary/headwords?seq=…` (repeated or comma-separated, follow the spec's existing array-param style), max 500 seqs (422 above), auth scope same as getDictEntry. Response `{items: [{seq, headword, reading}]}` where headword = first kanji form (or reading when kana-only) and reading = first reading; unknown seqs are omitted (not an error). Pick the final names/shape consistent with the rest of the spec. Add an example. Regenerate clients. Prefer this over changing the /cards Note shape.
