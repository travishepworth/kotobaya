# C-27 — Server/web: deck entries become new cards (materialize pending entries)

- Phase: P9 · Model: opus (architect role) · Risk: high (contract + server; reviewer + architect pass)
- Branch: t/C-27-materialize
- Owned paths: contracts/api, contracts/core (docs), server, clients/ (regenerate), web/src/lib/state/review.svelte.ts, web/src/routes/review/**
- Module(s) for CI: contracts, server, web

## Problem (live data, 2026-11-15)
The user cannot review on web: GET /review/queue returns ~nothing. Server QueueLoader passes
`pendingEntries = emptyList()` (server/src/main/kotlin/kotobaya/review/QueueLoader.kt:106), so deck
entries `e:<seq>` without a live note are never drawn as new cards (FOLLOWUPS T206 line ~151, C-26
minors). The user's decks (JLPT N1-N3, JPDB/Conversation Top 10k, media deck Fatal Twelve; ~35k
deck_item rows) have no notes; only 9 unsuspended new cards exist. Normal new-card intake (new_per_day
40) and Keep going (must be an unlimited stream: all due reviews regardless of the 200 cap, then
unlimited new cards, refilled automatically) both dry up. Android is fixed separately on device
(AND-KEEPGOING-FIX mints note.created origin "deck" + card.created on device).

## Do
1. Contract: decide how web materializes. Recommended: the server materializes inside
   GET /review/queue (or a new POST endpoint the web calls when `to_materialize` would be non-empty,
   your call; document it, ADR-032) by minting `note.created` (origin "deck") + default `card.created`
   ops through the op-apply path as the server device (CLAUDE.md rule 8), idempotent per entry_seq
   (never two live notes for one entry; consult SYNC.md dedupe/merge rules for races with devices),
   then returning the rebuilt queue. Pass real pendingEntries to the builder.
2. Server: build pendingEntries from deck_item of enabled decks with no live note for the entry (one
   batched query), respecting the builder's limits; keep_going batches refill on each fetch.
3. Web: keep going must never stop while a keep_going fetch returns items; refetch when the local queue
   empties; show the end screen only when a keep_going fetch is empty. Verify no repeated-card loop.
4. Regenerate clients.
