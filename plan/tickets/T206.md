## Do
- `GET /review/queue`: load the server replica rows, run the core `QueueBuilder` at request time with the user's time zone and settings, return the prefix with card, note summary, dictionary entry, example and scheduling preview data as the contract states.
- `POST /review/answer`: 4-button (again/hard/good/easy) and 5-button (nothing/something/okay) modes; emit `review.logged` with `review_type`, rating, button, `reviewed_at` from the server clock, `utc_offset_min` from the user's zone; fold the card cache through the T203 replay; return the next-state summary. Same card answered twice in the same ms is idempotent by request id per the contract.
- `POST /review/undo`: emit `review.undone` for the last review of the session/user per contract; the card cache returns to the exact prior state (replay without the undone row).
- Word status endpoints: never-forget, blacklist (`word.status_set` with origin `user`), clear.

## Acceptance (each bullet → at least one named test)
- [ ] Undo restores the exact prior card cache (stability, difficulty, due, state, reps, lapses) for new, learning, review and relearning cards.
- [ ] 5-button mapping logged as specified: nothing and something log rating 1 with the right button; okay rating 3; hard rating 2.
- [ ] Never-forget/blacklist cards never appear in the queue; clearing restores them.
- [ ] Drill/cram answers are logged and never change the schedule.
- [ ] A queue fetched after answering reflects sibling burying and limits.
- [ ] `make check MODULE=server` green.
