## Why
T103 built the device dictionary package (worker/src/kotobaya_worker/dict/package/; format described in that package's docstring) with formats that no contract fixes: the full package file (SQLite matching contracts/db/sqldelight Dict.sq, user_version 1, read-only, zstd-compressed), the diff format `kotobaya-dict-diff` v1 (per-table upsert/delete + row_counts, zstd JSON), and the object-storage key `blobs/<sha256-of-compressed>`. T302 (device install/update) and the server's GET /dict/release + GET /blobs/{hash} must agree with it without reading worker code.

## Do
- Write `contracts/db/DICT_PACKAGE.md`: exact package format (compression, SQLite user_version, read-only flag, table set = Dict.sq, integrity rules: no dangling rows, per-table row_counts), exact diff format v1 (envelope fields, per-table op lists, key columns per table, ordering, how `dict_release` changes, row_counts after apply, how a device verifies the result), hashes (which bytes are hashed; compressed vs uncompressed), blob key, versioning rules (additive; new format versions), and the device update algorithm (apply diff in one transaction, verify counts, fall back to full download on any mismatch).
- Reconcile with openapi `/dict/release` (`DictRelease`) and `/blobs/{hash}`: every field a device needs (release id, full package hash+size, diff from previous release hash+size, format versions) present; additive changes only. If T103's choices conflict with the API, prefer the API and list the worker changes needed in HANDOFF.
- Cross-check against T103's implementation (read-only) and list any mismatch.
