## Read

- Contracts: contracts/core/ `CardRenderer`, `CardClasses`, `Scheduler` (preview intervals), `ReplayEngine`; `assets/card/` (card.css defines `CardClasses.ALL`); contracts/sync/ops/review.logged + review.undone schemas, SYNC.md §7.9, §9; T303a `OpMinter`, T303b applier; T304a loader
- Decisions: ADR-002, ADR-005
- Follow-ups folded in: "T006 -> T213: assets/card/card.css must define CardClasses.ALL"; "T213a: {{pitch:}}/{{cloze:}} work only in built-in templates" (do not assume custom templates render pitch); "T203 architect: SET_DUE on NEW card leaves it unchanged" (the UI must not expect a due date)

## Do
- Review session: pulls the next card from `LocalQueueLoader` (T304a), renders it with core `CardRenderer` (JVM/Android target) into ONE reused `WebView` loading `assets/card/` from local assets (no network permission use: block all non-asset URLs, `allowFileAccess` limited, JS off unless needed for audio), front/back toggle, furigana toggle (app setting + per-session), pitch graph via the renderer.
- Native Compose grading bar, 4-button (Again/Hard/Good/Easy) and 5-button (Nothing/Something/Okay/Hard/Easy per the spec mode) with interval previews from core `Scheduler`; tap and swipe gestures (swipe right/left mapping per spec, configurable); each answer = `OpMinter.mint(review.logged)` in one transaction that also folds the cache (via T303b) and advances the queue. Request-id idempotency: double tap within the same ms mints one op.
- Undo: mints `review.undone` for the last answer in the session and restores the exact prior cache via replay; card returns to the front of the queue.
- Audio: play local audio from `blob_cache` when `cached`, autoplay setting, graceful no-audio state (prefetch is T310).
- Session summary, empty-queue state, a 'Sync' prompt when the outbox is large. Strings via i18n.

## Acceptance
- [ ] ViewModel/unit tests (Robolectric, JDBC DB): grading each button mints exactly one `review.logged` with the right `button`, `rating`, `review_type`, `reviewed_at` and `utc_offset_min`, and the card cache equals a fresh full replay; 5-button mapping matches the T206 server rules (nothing/something -> rating 1 with the right button).
- [ ] Undo: restores the cache exactly (new, learning, review, relearning cards) and the undone review is excluded from later replays; double undo does nothing.
- [ ] A refused-cache card never appears in a session (loader) and an answer on a card whose replay is refused still commits the op (T303b contract).
- [ ] Kill the process after answering: the op is in the outbox and the cache is updated (reopen DB).
- [ ] WebView test: the rendered page contains the expected classes/ruby markup for a fixture note and requests no network URL.
- [ ] `make check MODULE=android` green.

## Human checks
- On device, airplane mode: review 20 cards of mixed kinds, use each button, swipe and tap, undo twice, toggle furigana, play audio; kill the app; reopen; counts consistent. Then T303c's reconnect check.

## Out of scope
