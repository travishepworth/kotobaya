## Do
- Enqueue helper used by other tickets' endpoints (insert `app.job` with `dedupe_key` semantics: an already queued/running job with the same key is returned, per the OpenAPI), plus `/jobs`, `/jobs/{id}`, `/jobs/{id}/cancel` (cancelling a queued job is immediate; a running one sets a flag the worker polls, see T109b).
- **Define job retention** (FOLLOWUPS: T004; `importMedia.import_id` idempotency depends on job/media rows surviving). Decide and document in HANDOFF and a code comment: terminal jobs are kept for at least N days (suggest 90) and never pruned while `kind` is `media-import` or `jpdb-*-import` rows are the only record of an `import_id` (or keep those forever; they are small); only prune `succeeded`/`cancelled` jobs of other kinds and `failed` after N days. Provide a daily prune that the API runs in-process (no new CronJob), and a test proving a pruned job never breaks an `import_id` retry that the OpenAPI promises to answer (the most recent `media-import` job for that media, else 404).
- `/events` SSE: fan-out through Postgres LISTEN/NOTIFY (one dedicated connection per API process, channel documented), `job.updated` (at most one per job per second while running; terminal state always), `sync.changed` coalesced to one per second (emitter hook only; T202 raises it), `note.created`, `device.paired`/`device.revoked` from T105b's event bus. Close the stream when the credential is revoked/expired.
- Readiness gating: if T104 left a startup hook, this ticket adds none; just do not break it (FOLLOWUPS: C-1 -> T104/T111 puts the SYNC 10.5 replay behind readiness; T202 owns that).
- Env: `DATABASE_URL` only (JDBC form, LISTEN needs a non-pooled connection built from the same URL).
