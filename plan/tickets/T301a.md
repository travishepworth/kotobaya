- Feature registry: define `FeatureEntry` (id, nav routes, settings sections) and a Koin `featureModules` list in `di/FeatureModules.kt`. Every later ticket adds its package's Koin module plus ONE registration line there (flag it in HANDOFF); nobody else edits the nav graph.

- SQLDelight: add the plugin and point the source dir at `contracts/db/sqldelight/` (app + ref). Do NOT copy the .sq files, so drift is impossible. App DB (`kotobaya.db.app`) opens at app start and creates tables; the ref (dictionary) DB is a separate read-only file handled by T302, only wire an empty `DictionaryProvider` seam here. Unit tests get a JDBC `sqlite-jdbc` driver (`android/src/test`).

- i18n layer: all user-visible strings through `res/values/strings.xml` plus a thin `T`/`stringResource` helper; add a unit test that no Compose source under `android/src/main` hard-codes a user-visible literal (simple grep test is fine).
- Release build config: leave unsigned here (T312 owns signing).
- Robolectric available for unit tests (record the dependency).
