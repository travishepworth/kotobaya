## Evidence (orchestrator, run 8)
After D-2 merged, one `make check MODULE=worker` + `make check MODULE=server` (and the T506c writer's
runs of the same) grew `docker volume ls` from 195 to 216. New volumes carry only the label
`com.docker.volume.anonymous`, and appear in bursts: ~7 volumes ~4 s apart, then 1 ~20 s later
(15:07:22–15:08:03, 15:08:32–15:09:13, 15:19:18–15:19:58 local). Long-running containers present:
`postgres:17` (Up 4 h, probably the dev stack) and `testcontainers/ryuk`.

## Do
1. Find the source: e.g. run `docker events --filter type=volume --filter type=container` in the
   background while running ONE module's check at a time (worker first — no Gradle), and map each
   volume create to its container image + test. Also look for `docker run` in Makefile/scripts,
   GenericContainer uses without tmpfs, and Testcontainers images declaring `VOLUME`.
2. Fix at the source (tmpfs, `--rm` + anonymous-volume removal, `withTmpFs`, etc.).
3. Verify: the volume count is unchanged across a full `make check` of each affected module.

## Hard limits
Same as D-2: never prune or remove existing volumes/containers you did not create; check `df -h /`
first (BLOCKED under 10 GB); one Gradle module check at a time.
