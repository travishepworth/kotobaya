## Do
- `DeviceOpApplier` (implements T303a `OpApplier`) for EVERY op type in `contracts/sync/ops` per §7: register clock rule, creation rule, tombstones with cascade, whole-row values, timestamps, server-only values, missing targets as logged no-ops, idempotency by op id/natural key, `review_log` append-only (device apply refuses update/delete of review_log in code: the DB has no trigger on device), `review.undone` earliest-wins, `note.merged`/`card.merged` apply and forwarding of loser edits (§8.2-8.3). After any review/undo/params/preset/merge change, fold or fully replay the affected card caches through `ReplayEngine.decide/fold/replay` in the same transaction.
- Refused cache (§9.4): a refused replay writes the nil-UUID `last_review_id` cache (state new, nothing else kept), never fails the page/push/rebuild, records card id + error in a `DeviceDiagnostics` list; `decide` already answers FULL_REPLAY for such caches; verify.
- `core_scheduler_version` startup replay (§10.5): `StartupReplay.run(store)` before any sync/review/read; one transaction; idempotent; mints no op.
- Log reset (§6.2): when T303a reports `LogChanged`, in one transaction turn `acked` rows back to `pending` (per the contract), reset `pull_seq`, store new `log_epoch`/`durable_seq`, apply the auto-retry rule for `rejected` rows exactly as written, and trigger rebuild.
- Rebuild (§10.3): roll back local effects of discarded ops by re-deriving local registers from the log plus kept pending ops; `rebuild_pending` blocks minting; crash-safe and resumable; keeps `core_scheduler_version`.
- Reader helpers: effective identity of merged rows (§8.5).
