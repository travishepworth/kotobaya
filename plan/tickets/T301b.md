# T301b — Pairing (QR) and network client

- Phase: P3 · Model: sonnet · Risk: med
- Deps: T301a; T105b (pairDevice), W-2 (pairing codes) MERGED
- Branch: t/T301b-pairing
- Owned paths (only edit these): `android/src/main/kotlin/kotobaya/android/pairing/`, `android/src/main/kotlin/kotobaya/android/net/`, `android/src/test/kotlin/kotobaya/android/pairing/`, `android/src/test/kotlin/kotobaya/android/net/`
- Module(s) for CI: android

## Read
- Spec: Clients › Android app (Settings, devices), Sync and offline, Infrastructure › Security (device tokens, scopes)
- Contracts: contracts/api/openapi.yaml `pairDevice` (code, kind, 422 cases, token scopes), `getMeta` (limits: `max_op_bytes`, `max_push_bytes`, page size, `Kotobaya-Seq`), `devices/self`; clients/ (generated Kotlin client if one exists: use it, never hand-edit)
- Decisions: ADR-002 (public API only); HUMAN_CHECKS: PUBLIC_URL needed for the pairing URI
- Follow-ups folded in: "T105b: pairDevice returns 422 /kind when re-pairing a `script` device id with another kind" (show a clear error); "W-2: device pairing codes are in-memory (single API replica only)" (a failed pairing after a server restart must say 'code expired, make a new one'); "T005 -> T303: store the last /meta limits durably" (provide the `MetaLimitsStore` the sync client reads; T303c wires it)

## Do
- HTTP client (Ktor client or OkHttp: reuse what `clients/` generated, record dependency in HANDOFF) with base URL from settings, bearer token from the token slot, TLS via the system trust store, timeouts, and a typed error model (offline / unreachable / 401 / 403 scope / 5xx / body). One `ServerReachability` probe (`GET /meta`) used by sync and the UI.
- Pairing: QR scan (ML Kit or CameraX + ZXing; record choice) of the `kotobaya://pair?...` URI the web app shows, plus manual URL+code entry. Calls `pairDevice` with `kind=android`, stores `device_id` in `sync_state` (key `device_id`), token in encrypted storage, base URL in settings. Unpair clears token but keeps local data and the outbox.
- `MetaLimitsStore`: persists the latest `/meta` limits in `sync_state` (new key namespace `meta.*`, device-local, not part of the contract keys) and refreshes on every successful sync.
- Settings > Devices screen (this device only; list from `devices` API if the contract exposes it).

## Acceptance
- [ ] Unit tests with a fake server (MockWebServer or Ktor test engine): pairing success writes device id, token and base URL; wrong or expired code, 422 kind conflict, offline and 401/403 map to distinct typed errors.
- [ ] URI parser test: valid, missing-code and wrong-scheme `kotobaya://pair` URIs.
- [ ] `MetaLimitsStore` survives a process restart (re-open DB) and returns defaults only when never fetched.
- [ ] `make check MODULE=android` green. "Pairs with the dev server" is a Human check (below).

## Human checks
- With `make dev-up`: web app shows pairing QR, phone scans it, Settings shows the device paired and `GET /devices/self` works with the stored token.

## Out of scope
Sync protocol (T303*), dictionary download (T302), token refresh policy beyond re-pair.
