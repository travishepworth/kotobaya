## Do
- HLC service (server clock) with `hlc_last` persisted in `app.server_state`.
- `POST /sync/push`: parse leniently, validate each op (schema, scope, device id, clock bounds, size), apply idempotently in sequence within one transaction per SYNC §5.2, assign the server sequence (`change.seq`), per-op `accepted`/`duplicate`/`rejected` with the contract's codes.
- Op apply for every op type in `contracts/sync/ops` (register-clock rule, creation rule, tombstones with cascade, whole-row values, server-only values, missing-target handling, append-only `review_log`). Expose an `OpApply` entry point that REST handlers (T201b, T204, T206, T210a) and jobs (T207b) call to emit server-originated ops with the server device identity (CLAUDE.md rule 8).
- A hook interface called after `review.logged`/`review.undone`/params changes so the card cache can be (re)folded; T202c wires the real replay (T203). The default implementation must be a documented no-op.
- `GET /sync/pull`: ordered pages after a seq, `log_epoch`, tombstones included, page size per `/meta` limits.
- Same-entry merge, restore handshake, durable_seq and fuzz are T202c: leave extension points only.

## Acceptance (each bullet → at least one named test)
- [ ] Every worked example in SYNC.md §12.1-12.4 and every `contracts/sync/examples/raw-push` case is a passing test, including `same-op-id-equal-contents`.
- [ ] Idempotency: re-pushing a batch applies nothing twice and returns `duplicate`; out-of-order delivery (op before its creator, tombstone before edit) follows §7.7.
