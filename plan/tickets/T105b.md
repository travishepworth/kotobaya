## Do
- Device pairing: short-lived code shown as a QR, held in memory (SUMMARY known gap: a restart invalidates codes; document it). `POST /devices/pair` returns a `kbd_` token with scopes read/write/review.
- Personal access tokens with chosen scopes and optional expiry, hashed at rest, string shown once.
- Scope-enforcement middleware driven by the OpenAPI per-operation `security` scopes. Generate the table from `contracts/api/openapi.yaml` at build or test time; never hand-copy it.
- Implement `x-auth: body-key` / `x-body-key-scope` by hand for `/ankiconnect` (FOLLOWUPS: T004 -> T105).
- `POST /cards/bulk/schedule` needs only `review` per the contract; FOLLOWUPS suggests `review`+`write`. Implement as specified and list it in HANDOFF as a CONTRACT_CHANGE_REQUEST candidate; do not change the contract.
- Revoking a device or token must end open `/events` streams. Expose a small revocation/event bus that T109a serialises to SSE and ntfy, and emit `device.paired` / `device.revoked` on it.

## Acceptance (named tests)

- [ ] Pairing: single use, expiry, re-pair overwrites and clears `revoked_at`, wrong codes are rate limited.
- [ ] `/ankiconnect` body-key accepted only there and only with scope `write`.
