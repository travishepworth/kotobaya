## Do
- `JpdbDeckSource` protocol returning a typed `DeckVocabulary` (title, list of `{vid, spelling, reading, occurrence_count, global_rank_bucket|None}` plus raw-row count) with two implementations:
  - **Pages** (default, no key): `<deck>/vocabulary-list?offset=N` paging via the "Next page" link, `sort_by=by-frequency-local`; parse vid from the link, spelling from the slug, reading from `<rt>` (absent for kana words), occurrence count, "Top N" rank bucket. Title from the deck page.
  - **API** (when `JPDB_API_KEY` is set): port the spike's `deck_vocabulary`; the endpoint names are unverified — keep the response mapping in one function and make the source fall back to Pages on a schema mismatch, logging why.
- **Rate limit** ≥ 2 s between network calls (injectable clock/sleeper). **Cache**: every response stored on disk under `JPDB_CACHE_DIR` (default `~/.cache/kotobaya-jpdb`), keyed by URL/request without the API key; a `max_age` policy (default: reuse forever unless `refresh=True`); a cached run makes zero network calls. Stdlib only (urllib, html.parser) — no new dependency.
- Tolerate shape drift: rows the parser cannot read are returned in a `skipped` list with the raw snippet, never dropped silently.
- Self-written fixture pages in `fixtures/jpdb/deck/` (CC0, structure copied from the spike's description, values invented): 3 pages with a next link, kana-only rows, a row without rank, one malformed row; plus a mocked API response.
