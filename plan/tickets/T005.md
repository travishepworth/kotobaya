## Must also resolve (from T003 review follow-ups)
1. Convergence definition: two-level merges leave tombstoned intermediate rows (L1→W'→W after flattening) with differing registers/clocks across replicas; live rows converge. Either define convergence = live rows + merged_into_id (and say so for the fuzz test), or forward along the un-flattened chain.
2. Loser deleted_at order dependence: merge step sets deleted_at only if NULL (note.merged and card.merged) — state it.
3. Merge triggered by an entry_seq write that later loses LWW stays merged; arrival-order dependent re-match outcome (also delete racing a duplicate) — state explicitly as accepted trade-offs.
4. Concurrent note.deleted on the survivor hides a duplicate's cards (reviews remain in review_log) — document.
5. deck_item `n:<loser id>` resolves through merged_into_id (as confusable does).
6. Device-side append-only + earliest-undo-wins are apply-code rules — specify them precisely so T006/T107 tests can cover them.
7. Rejected ops (client-originated media/list deck.created, review for unknown card, schema-invalid): define how a rejected pending_op's local effect is rolled back or surfaced to the user (rejected ops are never auto-purged).
8. A duplicate's filled fields are copied to the survivor even if the duplicate was deleted before push — document.
