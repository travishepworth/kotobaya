# F-6 — Android sync DB: schema missing when first use is a transaction

- Module(s) for CI: android

## Problem (reported by T305c writer)
If a SqlDelightDeviceStore transaction is the sync DB's first use in the process, the learning tables stay missing for the whole process (schema create/migrate never runs or runs inside the rolled-back/failed tx). A Takoboto cold start (AnkiDroid provider call before the app UI) hits this. T305c worked around it with a plain query at store construction.

## Do
- Ensure schema create/migrate runs exactly once, eagerly, outside any caller transaction, when the durable driver/database is first obtained (e.g. force open in the Koin single / DurableDriver.open).
- Remove the need for T305c's workaround (leave its call harmless if T305c is not yet merged; if merged, delete the workaround query in ankiapi/store/ — allowed).
- Also (FOLLOWUPS T303c): re-assert `PRAGMA synchronous=FULL` per transaction start or verify it applies to every connection.
