# parse/ — sentence segmentation fixtures

- Origin: 200 sentences written for this project (s01-s20 first, s21-s200 added by ticket F-7). Tokenisation is hand-authored in the style of Sudachi: compounds kept (mode C) where JMdict has an entry for the whole, otherwise split as in mode B; verbs/adjectives split into stem + auxiliaries. Sudachi was not run: the file is the expected output, not a Sudachi dump, and every sentence was hand-reviewed.
- Produced by `fixtures/tools/gen_parse_sentences.py` from the hand-written token lists and lexicon in `fixtures/tools/parse_sentences_src.py` (s01-s20 are kept verbatim; the tool only adds `seq`). Edit the source and regenerate; do not hand-edit the JSON.
- Licence: CC0.
- `sentences.json`: `{id, text, translation, tokens[{surface, lemma, reading, pos, seq}]}`; token surfaces concatenate exactly to `text`. Readings are hiragana. Lemmas are covered by `dict/JMdict_subset.xml` or `dict/JMdict_parse_extra.xml` (except pos `punct`/`name`/`symbol`/`number`).
- `seq` (optional-by-value, always present, may be null): the JMdict `ent_seq` when the lemma + pos class identify one entry (ties broken by a priority tag on the matching form); null when ambiguous, and always null for punctuation, names, numbers and symbols. About 89% of content tokens carry a seq.
- pos values: noun, pronoun, verb, adjective, adjectival-noun, adverb, particle, auxiliary, adnominal, numeral, suffix (counters), prefix, interjection, punct, name, number (digit strings; lemma NFKC-normalised, e.g. `１０` -> `10`), symbol (Latin letters).
- Coverage: te/ta/nai/masu/tai/rareru/saseru chains, mode-C compounds, mode-B fallbacks (s53..s64 keep, s65..s76 split), kana-only spellings (lemma is the kanji form), iteration marks (々, ゝ), full/half-width digits, letters and katakana, counters, loanwords, person/place names, sentence-final particles, ちゃう/てる/なきゃ contractions, subtitle-style fragments.
